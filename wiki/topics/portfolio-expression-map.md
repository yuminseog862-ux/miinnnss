# Portfolio Expression Map

이 문서는 기존 `crossangle`, `creative`, `tainai` 포트폴리오에서 반복된 표현 구조와 프로젝트별 문구 방향을 한 곳에 모은다. 목적은 새 페이지를 만들 때 바로 가져다 쓸 수 있는 표현 기준을 유지하는 것이다.

## 공통 구조

세 포트폴리오 모두 좋은 반응을 기대할 수 있는 구조는 비슷하다.

1. 한 문장 포지셔닝: 이 사람이 어떤 문제를 어떤 방식으로 다루는지 먼저 말한다.
2. 역할과 범위: 리서치, 기획, 구현, 콘텐츠, 운영 중 직접 맡은 범위를 분리한다.
3. 행동 루프: 문제 정의 -> 작업 -> 공개/검증 -> 다음 판단을 짧게 보여준다.
4. 증거: 화면, 영상, 문서, 포스트, 플로우, 리비전 중 하나를 바로 붙인다.
5. 판단: 결과 수치를 만들지 않고, 확인된 신호와 다음 결정을 남긴다.

## 공통 레이아웃 규칙

- 첫 화면: 큰 주장 1개, 보조 설명 2문장 이하, 증거 3개 이하.
- 케이스 페이지: `Problem`, `Role`, `Action`, `Proof`, `Decision` 순서가 가장 안정적이다.
- 슬라이드형 페이지: 한 페이지에 하나의 판단만 둔다.
- 증거 이미지는 꾸미기보다 문장을 증명하는 위치에 둔다.
- 긴 설명 대신 카드 제목에 결론을 넣고, 본문은 근거와 행동만 적는다.

## 공통 문체 규칙

- 기본은 한국어로 쓴다.
- 채용 담당자가 빠르게 읽을 수 있게 짧은 명사형보다 행동이 보이는 문장을 쓴다.
- 확인되지 않은 지표, 반응, 성과는 쓰지 않는다.
- 성공하지 않은 프로젝트도 숨기지 않고 `보류 판단`, `중단 판단`, `범위 축소`처럼 판단 품질로 정리한다.
- `AI를 활용했다`보다 `AI로 무엇을 더 빠르게 판단하거나 제작했는지`를 쓴다.

## CrossAngle / Xangle GTM

### 포지셔닝

Web3 리서치를 GTM 산출물로 전환한 AHEYABARAYA 케이스.

### 반복 구조

- Research: EVM/Base, Solana, residual asset, Virtual Protocol, ACP v1.
- Structure: 문제 정의, 사용자, 해결 구조, 근거, 업데이트 노트.
- Publish: X 포스트, 짧은 훅, 이미지/영상 콘텐츠.
- Operate: 포스팅 목적, 다음 판단, 업데이트 기준.

### 쓸 만한 표현

- Web3 사용 흐름을 직접 겪고 리서치 질문으로 바꾼 기록.
- 리서치를 사용 가능한 정보 구조로 바꾼다.
- 프로젝트 정보를 X 콘텐츠와 시각 자산으로 낸다.
- 콘텐츠를 목적과 다음 판단 기준으로 관리한다.
- 소액 온체인 자산의 사용 공백을 제품/서비스 소비 흐름으로 다시 정의했다.

### 주의할 표현

- `수요를 검증했다`는 식으로 쓰지 않는다.
- X 포스트는 반응 성과보다 hook, 대상 독자, 자산, 발행 목적, 다음 업데이트 기준으로 설명한다.

## Creative Planning

### 포지셔닝

캐릭터와 세계관을 더 빠르게 읽히는 구조로 설계한다.

### 반복 구조

- Identity / Worldbuilding: 정체성 해석, 세계관 구조화, 상징 모티프 연결.
- Character / Persona Planning: 성격, 관계, 말투, 감정선.
- Visual Concept / Moodboard: 레퍼런스 리서치, 콘셉트 축소, 이미지/영상 실험.
- English Writing / Research Framing: 영문 초록, 포스터 구조, 외부 제출 문서.

### 쓸 만한 표현

- 정체성과 감정을 캐릭터, 상징, 비주얼 콘셉트로 번역한다.
- 서비스 설명만으로 부족한 첫인상을 캐릭터와 세계관으로 보완했다.
- 메인 캐릭터와 연결 캐릭터를 함께 두어 설명을 관계성으로 확장했다.
- 무드보드와 레퍼런스 리서치를 바탕으로 비주얼 콘셉트를 좁혔다.
- 브랜드 해석과 아이디어를 영어 문서와 포스터 구조로 정리했다.

### 주의할 표현

- 이미지 자체보다 이미지가 해결한 커뮤니케이션 문제를 앞에 둔다.
- 세계관 자료는 감상형 나열이 아니라 유입, 첫인상, 관계성, 채널 문구와 연결한다.

## TainAI

### 포지셔닝

추상적인 아이디어를 기능과 화면으로 빠르게 바꾸고, 직접 반응을 본 뒤 다음 결정을 내린다.

### 반복 구조

- 문제 정의: 무엇이 막히는지 짧게 잡는다.
- MVP 구현: 실제 화면이나 흐름으로 만든다.
- 공개/직접 테스트: 작은 반응을 본다.
- 결정: 개선, 보류, 중단, 범위 축소 중 하나를 남긴다.

### 쓸 만한 표현

- 문제 정의 -> MVP 구현 -> 공개 테스트 -> 결정.
- 아이디어를 기능과 흐름으로 빠르게 구조화했다.
- 테스트 피드백을 보고 UX를 고쳤다.
- 신호를 보고 줄이거나 멈췄다.
- 반응이 약하거나 불편 신호가 크면 더 키우지 않고 멈추거나 범위를 줄였다.

### 주의할 표현

- 중단한 실험을 성공 사례처럼 포장하지 않는다.
- `빠르게 만들었다`보다 `무엇을 확인하기 위해 어느 범위까지 만들었는지`를 쓴다.

## 프로젝트별 표현 뱅크

### AHEYA / AHEYABARAYA

- 참여형 Web3 서비스의 초기 유입을 만들기 위해 캐릭터 세계관과 공개 채널 콘텐츠를 함께 기획했다.
- 방치되는 소액 온체인 자산을 Dust mode의 소액 후원 흐름으로 다시 정의했다.
- 서비스 이해를 돕는 화면과 신뢰를 설명하는 화면을 분리했다.
- 공개 가능한 MVP를 만들고, 운영 실험과 보류 판단까지 이어갔다.

### ADSB / Andersson Bell

- 무드보드와 레퍼런스 리서치로 브랜드 톤을 좁히고 AI 이미지/영상 실험으로 결과 방향을 확인했다.
- direction, draft, production 단계를 분리해 제작 판단을 읽히게 했다.
- 결과물보다 어떤 레퍼런스를 선택하고 무엇을 줄였는지 보여준다.

### AB-Luna / Relay

- 서로 다른 LLM 플랫폼 사이의 상태 공유와 handoff 단절을 공통 상태 저장소 MVP로 풀어보았다.
- 버튼이 많아 첫 행동을 찾기 어려운 지점을 보고 홈과 세션 UX를 단순화했다.
- session detail과 dashboard를 통해 작업 맥락이 이어지는 구조를 보여준다.

### ILYSB

- 모바일 실험을 직접 테스트한 뒤 불편 신호와 전환 약함을 확인하고 중단 판단을 남겼다.
- login, signup, explore, hint unlock까지 이어지는 실제 플로우를 증거로 둔다.
- 중단 판단을 실패 회피가 아니라 다음 작업 범위를 정한 판단으로 설명한다.

### SFTI / CMU

- 브랜드 해석과 아이디어를 영어 문서와 포스터 구조로 정리했다.
- 리비전 전후 자료를 통해 문서와 시각 구조가 어떻게 다듬어졌는지 보여준다.
- 외부 제출형 결과물은 결과보다 제출 가능한 구조와 표현 완성도를 강조한다.

## 새 페이지 작성 체크리스트

- 이 페이지의 한 문장 결론이 있는가.
- 직접 한 역할과 팀/외부 결과를 섞지 않았는가.
- 각 주장 옆에 이미지, 영상, 문서, 플로우 중 하나가 붙어 있는가.
- 숫자나 성과 표현은 실제 근거가 있는가.
- 마지막에 다음 판단, 보류, 중단, 개선 방향 중 하나가 남는가.

## Portfolio Skill 후보

다음 표현은 portfolio 전용 skill이나 slide template로 올릴 가치가 있다.

- `Problem -> Action -> Proof -> Decision` 케이스 카드.
- `Research -> Insight -> Publish -> Operate` GTM 카드.
- `Identity -> Character -> Visual -> Channel` creative 카드.
- `Hypothesis -> MVP -> Test -> Decision` PM/AI workflow 카드.
- `보류/중단 판단을 숨기지 않는 케이스` 작성 규칙.
