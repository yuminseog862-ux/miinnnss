## 최종 판단

이 페이지의 차별점은 많은 AI 도구를 사용했다는 사실이 아니다.

> 새로운 AI 변화에서 제작 가능성을 발견하고, 실제 콘텐츠에 붙여 본 뒤, 성공과 폐기에서 얻은 판단을 다음 제작 방식으로 바꾼 과정

이 문장을 증명하는 포트폴리오로 정리했다. 처음부터 하나의 제작 병목을 해결한 것처럼 쓰지 않고, AHEYA 마케팅 콘텐츠에서 발견한 가능성이 Aurora·MV·Workbench로 커진 과정과 작업마다 새로 드러난 문제를 구분했다. Workbench·Edit Desk·production system은 주인공이 아니라, 반복 실험이 남긴 결과와 근거로 배치했다.

공고의 평가 순서는 다음과 같이 해석한다.

팀워크는 이 개인 탐구 페이지에서 억지로 증명하지 않는다. MUSINSA 3인 팀과 ADSB 산학의 피드백 경험은 이력서·자기소개서·면접에서 담당한다.

완료하지 않은 공간·리테일 작업도 실적으로 쓰지 않는다. 이 항목은 입사 후 확장 가능성으로만 말한다.

## 최종 읽기 순서

1. **Hero / Answer First**: `AI의 변화를 실제 콘텐츠에 붙여 봅니다.`라는 포지셔닝, 핵심 질문, 현재 결론, 3 completed·2 discarded·26 Aurora units 증거
2. **01 Origin**: AHEYA marketing content → context-aware generation → Aurora 26 units → full MV hypothesis
3. **02 Trend Log**: 새 기능에서 발견한 가능성·제작 문제 → 질문 → 실제 시험 → 채택·부분 채택 → 다음 변화
4. **03 Repeated Experiment**: Root Signal → LOW → Pulso → Left in That Night → INK → Workbench의 실제 변화 지도
5. **04 Outcomes**: INK 콘텐츠, Loom IP 경험, Workbench·Edit Desk·harness, archive·decision log를 `04A—04D`로 제시
6. **05 AHEYA**: 별도 서비스·스마트계약·OpenClaw Yui 탐구와 중단 판단
7. **Closing**: 직무에 가져갈 세 가지와 주장 경계

결과는 Hero에서 먼저 예고하고 04에서 과정과 함께 증명한다. 결과를 너무 늦게 보여주는 문제와, 결과부터 설명해 탐구 과정을 약하게 만드는 문제를 동시에 피했다.

## 실제 레포 대조 결과

### IDOL / Loom

- 공개 track data에 `Root Signal`, `Pulso`, `INK Final Master`가 연결돼 있다.
- 실제 제작 순서는 `Root Signal(05.24) → LOW(05.26) → Pulso(06.11) → Left in That Night(06.14) → INK(06.18) → Workbench(07)`다.
- Root Signal은 v11 final closeout, LOW는 폐기 후 face reference·편집 규칙, Pulso는 final completion, Left in That Night는 formal discard와 anti-repeat rule, INK는 final master와 track board가 남아 있다.
- Signal Deck에 13명 identity, TikTok clips, Harne identity vote, member message, next-track vote가 구현돼 있다.
- 투표와 메시지는 로컬 프로토타입이며 공개 서비스 성과로 주장하지 않는다.

### Aurora V1 → V2

- V1은 생성, 리서치, 검토, 게시, 분석을 한 트리에서 다뤄 생산적이었지만 active canon을 혼동하기 쉬웠다.
- V1을 지우지 않고 archive provenance로 보존한 뒤 V2에서 조사·선정·패킷·생성·사람 검토를 분리했다.
- 13 MV와 13 STAGE의 실제 통과 보드 중 M01·M11 쌍을 공개 증거로 사용했다.
- 26개 공개 작품이라고 표현하지 않고, identity continuity와 반복 제작을 확인한 제작 단위로 한정했다.

### IDOL production system

- Workbench의 실제 product contract는 생성 이미지보다 plan과 founder selection을 우선한다.
- Workbench는 실행 가능한 개발 checkpoint지만 real-song scale acceptance는 완료되지 않았다.
- Edit Desk는 Python/Tk 기반 로컬 편집 보조 MVP이며 Premiere Pro·After Effects 대체 제품으로 주장하지 않는다.
- ffprobe, ffmpeg, OpenCV, librosa는 소스·프레임·움직임·비트 관찰과 roughcut·QC에 사용한다. 분석값이 좋은 컷을 자동 결정하지 않는다.
- stage registry의 공개 발췌는 stable semantic ID, one canonical owner, upstream revision 원칙만 보여준다.

### X·TikTok 분석

- 실제 플랫폼 signal report와 performance loop가 있다.
- 플랫폼별 공개 지표를 비교하지만 creative causality를 주장하지 않는다.
- 분석 후보는 `founder_review_required`, `not_applied` 상태로 남고 사람이 승인해야 다음 실험에 반영된다.

### AHEYA

- 영상 제작 production system과 별개의 개인 서비스 탐구다.
- 공개 Solidity artifact와 OpenClaw Yui의 탐색→계획→실행→검토→기록 흐름을 근거로 사용한다.
- 스마트계약 상용 배포, 자율 거래 성과, 시장 채택은 주장하지 않는다.
- 약 2~3주의 직접 접촉에도 유효한 시장 반응이 없어서 중단했고, 이 판단이 콘텐츠 제작 실험으로 방향을 바꾸는 계기가 됐다.
