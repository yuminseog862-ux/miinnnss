## 1. 최종 포지셔닝

> 새로운 AI 변화를 실제 제작 병목에 붙여 보고, 성공과 폐기에서 얻은 판단을 다음 제작 구조로 바꾸는 AI Creative 신입.

보조 설명:

> 패션마케팅을 전공하고 브랜드 메시지와 톤을 영상 흐름으로 번역해 왔습니다. AHEYA의 crowdfunding·Trust 탐구에서 시작해 Yui, 26개의 IDOL 제작 단위, MV의 반복 실패와 개선, INK, Front Planning Workbench로 이어지는 AI Exploration을 직접 진행했습니다.

정규 개발자, ML 연구자, LLMOps 경력자로 포지셔닝하지 않는다. 모든 제작 및 개발 근거는 개인 프로젝트, 팀 프로젝트, 산학 프로젝트의 범위로 쓴다.

## 2. 자기소개서와 면접의 서사 순서

1. **MUSINSA와 ADSB로 시작**  
   브랜드 메시지와 패션 무드를 장면 흐름으로 옮기고, 기준에서 벗어난 후보를 걸러낸 경험을 짧게 제시한다.

2. **AI Exploration의 출발점과 질문을 먼저 제시**  
   `기획만 명확하다면, 한 사람이 AI를 하네싱해 스튜디오처럼 반복 가능한 영상 제작 루프를 만들 수 있을까?`를 중심 질문으로 둔다. AHEYA crowdfunding -> Trust API/Yui -> marketing image·clip -> Aurora 26개 단위 -> full MV 순서로 설명한다.

3. **성공보다 하네스가 바뀐 실패를 제시**  
   Root Signal의 반복적인 카메라·빛, LOW의 face lock 실패, Left In That Night의 감정·인과 실패가 각각 창의 작업 비스크립트화, face reference gate, pre-board stop rule로 바뀐 과정을 보여준다.

4. **Pulso와 INK로 개선 결과를 증명**  
   Pulso는 frame·beat 기반 편집 보조, INK는 camera·light·object·곡 section 기획과 얼굴 유지가 실제 영상과 contact sheet로 이어진 사례다. 현재 공개 영상은 INK 하나만 사용한다.

5. **Workbench와 전체 production system을 실험의 결론으로 제시**  
   생성보다 기획이 병목이라는 판단에서 Workbench를 만들었고, 이후 8 phase·29 stage가 실행을 이어받는다. 반복은 자동화하고 메시지, 톤, 선택, 유료 실행, 외부 공개는 사람이 책임진다.

`AI Experience / AI Creative`

### Profile

패션마케팅을 전공하고, 새로운 AI 기능을 실제 제작 병목에 적용해 실패와 개선 과정을 기록해 온 신입/졸업예정자입니다. MUSINSA와 ADSB에서는 브랜드 메시지와 패션 무드를 영상 흐름으로 번역했습니다. 개인 AI Exploration에서는 AHEYA의 Trust 실험에서 시작해 26개의 IDOL 제작 단위, 여러 MV의 폐기와 개선, INK, Front Planning Workbench, 8개 phase·29개 stage production system으로 작업 방식을 발전시켰습니다.

- **AI Exploration:** 새 기능을 실제 제작 병목에 적용하고 실패 원인과 다음 system update를 run·review 기록으로 관리
- **AI Production System:** stage owner, source binding, schema validation, pass·hold·reject, explicit approval을 포함한 전체 제작 구조 설계
- **Media Analysis & Edit Assist:** ffprobe, OpenCV, librosa, Pillow, MoviePy, ffmpeg를 활용한 source intake, contact sheet, roughcut, QC
- **Brand Content:** MUSINSA 캠페인 메시지와 ADSB 브랜드 무드를 숏폼의 장면 순서와 톤으로 번역
- **Service & Trust Exploration:** Solidity smart contract와 Trust API 기반 candidate snapshot, plan, execution, strict review, canonical record 구현 탐구

## 9. 주장 금지선

- AHEYA smart contract를 상용 배포 또는 채택 성과로 쓰지 않는다.
- Yui가 지속 자율 거래를 수행하거나 시장 성과를 냈다고 쓰지 않는다.
- Workbench를 production-complete 또는 실제 곡 승인 도구로 쓰지 않는다.
- Codex와 Grok의 환각률 또는 품질 우열을 개인 비교 결과로 쓰지 않는다.
- Python 분석값이 좋은 장면과 컷을 자동 선택했다고 쓰지 않는다.
- Pulso, INK, AHEYA를 정규 실무 경력으로 쓰지 않는다.
- 이번에 완료 근거가 없는 리테일·공간 프로젝트를 실적으로 넣지 않는다.
